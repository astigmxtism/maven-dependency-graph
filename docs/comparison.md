# Сравнение со штатной визуализацией Maven

Сравнение выполнено на этапе 5 для трёх реальных release-пакетов
из `https://repo.maven.apache.org/maven2`.

## Окружение и воспроизведение

- Apache Maven **3.9.9**.
- Maven Dependency Plugin **3.8.1**, цель `tree`.
- Java **21.0.10**, Oracle Corporation.
- Python **3.13.7**, Windows, UTF-8.

```console
py -3 tools/compare_maven.py --bootstrap
```

Скрипт использует только стандартную библиотеку. При отсутствии Maven
скачивается официальный дистрибутив с проверкой SHA-512.
Дистрибутив, локальный кеш и отдельный проект потребителя располагаются
во временной папке и удаляются после сравнения.

У каждого временного проекта одна зависимость — выбранный пакет.
Штатная команда внутри такого проекта:

```console
mvn -q -B -ntp -Dmaven.repo.local=<временный-кеш> org.apache.maven.plugins:maven-dependency-plugin:3.8.1:tree
```

Дополнительные аргументы той же команды:

```text
-Dscope=runtime -DoutputType=text -DoutputFile=<временная-папка>/tree.txt
```

Это отдельная проверка результата: основной инструмент не вызывает Maven
и не использует его вывод для построения своих графов.

## Итог сравнения

Из результата Maven удалена только техническая вершина
`comparison:consumer:jar:1`. Обозначения `type` и `scope` приведены к GAV,
который использует приложение. Затем независимо сравнены **множества вершин
и ориентированных рёбер**, а не только их количество.

| Пакет | Python: вершины / рёбра | Maven: вершины / рёбра | Множества совпали |
| --- | --- | --- | --- |
| `junit:junit:4.13.2` | 2 / 1 | 2 / 1 | Да |
| `org.slf4j:slf4j-simple:2.0.16` | 2 / 1 | 2 / 1 | Да |
| `org.apache.httpcomponents:httpclient:4.5.14` | 4 / 3 | 4 / 3 | Да |

Во всех трёх случаях скрипт вывел:

```text
Совпали вершины: True; совпали рёбра: True
```

Расхождений в составе этих трёх графов **не обнаружено**.

## Почему представления могут отличаться

1. Maven рисует дерево проекта потребителя, приложение — граф выбранного
   пакета. Техническая обёртка потребителя не является зависимостью.
2. На этапе 2 выводились все прямые объявления POM. Runtime-граф этапа 5
   исключает `test`, `provided`, `system`, `optional`, как зависимости
   потребителя. Поэтому, например, `hamcrest-library` из тестов JUnit
   присутствует в отчёте этапа 2, но отсутствует в обоих сравниваемых графах.
3. В общем случае приложение сохраняет разные версии одного артефакта
   как отдельные GAV-вершины. Maven выбирает ближайшую версию, а при равной
   глубине — первую объявленную; он также применяет управление версиями
   корневого проекта к транзитивным зависимостям. Эту медиацию приложение
   не воспроизводит. В выбранных трёх примерах конфликта версий нет.
4. Граф сохраняет общие и циклические рёбра. Дерево Maven может скрывать
   повторные узлы; в ASCII приложения они помечаются `[shared]`/`[cycle]`.
5. Профили, настройки Java/ОС, SNAPSHOT, диапазоны, relocation и дополнительные
   репозитории вне заданного URL не моделируются. Для таких проектов
   результаты потребовали бы отдельного анализа контекста сборки.

Три полученных SVG и их PlantUML/ASCII-представления описаны
в [отчёте визуализации](stage-5.md).
