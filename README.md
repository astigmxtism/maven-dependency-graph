# Граф зависимостей Maven

Практическая работа, вариант №2. Язык — Python 3.10 или новее.
Для работы приложения и тестов достаточно стандартной библиотеки.

Приложение получает Maven POM напрямую по HTTP(S), строит граф
рекурсивным BFS, создаёт PlantUML и SVG, выводит ASCII-дерево.
Есть файловый тестовый репозиторий и режим обратных зависимостей.

## Запуск и конфигурация

```console
run.bat --config config.ini
```

Обычный запуск создаёт изображение и открывает его в браузере по умолчанию.
Для полностью автономного примера с ASCII и PlantUML:

```console
run.bat --config examples/test/cycle.ini
```

В Linux/macOS: `sh run.sh --config config.ini`.
Можно также выполнить `python run.py --config config.ini`.
В Windows вместо `python` доступна команда `py -3`.

Если аргумент `--config` не задан, используется `config.ini` из корня
проекта. Все параметры анализа читаются из INI, а не из аргументов CLI.

```ini
[settings]
package = junit:junit:4.13.2
repository = https://repo.maven.apache.org/maven2
test_mode = false
ascii_tree = true

[visualization]
output_dir = output
plantuml_url = https://www.plantuml.com/plantuml
render = true
open_image = true
```

| Ключ | Значение |
| --- | --- |
| `package` | Координаты `groupId:artifactId:version`; в тестовом режиме — `A`, `B`, `AA` и т. п. |
| `repository` | HTTP(S)-адрес Maven-репозитория или путь к файлу тестового репозитория |
| `test_mode` | Выбор файлового тестового репозитория |
| `ascii_tree` | Включение ASCII-дерева на этапе визуализации |

Все четыре ключа обязательны. Логические значения: `true/false`,
`yes/no`, `on/off`, `1/0`, без учёта регистра. Пути разрешаются
относительно INI-файла. Кодировка — UTF-8, допускается BOM.
Приложение показывает сводку графа, ASCII при включении и пути результатов.
Список всех параметров выводится только в коммите первого этапа.

### Параметры визуализации

Секция `[visualization]` необязательна. Если она отсутствует,
используются значения по умолчанию:

| Ключ | По умолчанию | Назначение |
| --- | --- | --- |
| `output_dir` | `output` в корне проекта | Папка для `.puml` и `.svg` |
| `plantuml_url` | `https://www.plantuml.com/plantuml` | HTTP(S)-сервер рендеринга PlantUML |
| `render` | `true` | Получать SVG по тексту диаграммы |
| `open_image` | Значение `render` | Открывать локальное SVG в браузере |

Явно заданный относительный `output_dir` отсчитывается от INI.
При `render=false` сохраняется PlantUML и работает ASCII-вывод;
для тестового JSON-репозитория сеть тогда вообще не требуется.
Для получения SVG нужен доступ к выбранному PlantUML-серверу.
На сервер передаётся готовая диаграмма; зависимости извлекает Python-приложение.
При ошибке рендеринга уже записанный `.puml` сохраняется.

`[cycle]` в ASCII означает цикл текущего пути, `[shared]` — повторно
встреченную общую зависимость. Их поддеревья повторно не раскрываются.

## Обработка ошибок

Ошибка выводится в stderr с префиксом `Ошибка:`; код завершения — `2`.
Успешный запуск возвращает `0`.

Проверяются отсутствие/недоступность INI, его синтаксис, секция
`[settings]`, пропущенные, повторяющиеся и неизвестные ключи,
оба логических параметра, формат имени пакета, схема и корректность URL,
существование и доступность тестового файла. Секция `[DEFAULT]`
не используется. Разрешены `[settings]` и необязательная `[visualization]`.
Проверяются также все параметры визуализации и обратного поиска.
Ошибки JSON, POM, HTTP, записи результата и запуска просмотрщика
выводятся без трассировки стека с ненулевым кодом завершения.

Воспроизводимые примеры ошибок и правильного запуска приведены
в [отчёте первого этапа](docs/stage-1.md).

## Проверки

```console
py -3 -m unittest discover -s tests -t . -v
py -3 tools/check_quality.py
py -3 tools/check_repository.py --history
```

Проверка качества контролирует длину файлов, строк и функций,
число аргументов, сложность, docstring и числовые литералы в сравнениях.
Имена модулей, функций и переменных следуют PEP 8.

Тесты автономны: сеть и системный просмотрщик заменены тестовыми объектами.
Фактические SVG проверяются как XML, без GUI:

```console
py -3 run.py --config examples/maven/junit.ini
py -3 run.py --config examples/maven/slf4j.ini
py -3 run.py --config examples/maven/httpclient.ini
py -3 tools/verify_examples.py
```

Эти три INI используют `open_image=false`, поэтому подходят для CLI-проверок.
Примеры SVG, ASCII и PlantUML описаны в [отчёте этапа 5](docs/stage-5.md).

## Чтение Maven POM

Пример: `py -3 run.py --config examples/maven/httpclient.ini`.
POM загружаются напрямую по HTTP(S) с таймаутом. Поддерживаются
родительские POM, свойства, `dependencyManagement` и импорт BOM.
Сторонние библиотеки и Maven для работы приложения не требуются.

Подробнее: [этап 1](docs/stage-1.md), [этап 2](docs/stage-2.md).

## Тестовый граф и транзитивность

```console
py -3 run.py --config examples/test/diamond.ini
py -3 run.py --config examples/test/cycle.ini
```

Файловый репозиторий — JSON-объект `{"A": ["B"], "B": []}`.
Поддерживаются циклы, петли, общие зависимости и несвязные компоненты.
Maven-граф включает обязательные compile/runtime-зависимости потребителя,
учитывает exclusions и сохраняет разные версии как отдельные вершины.

Поддерживаются конкретные release-версии, один заданный репозиторий,
унаследованные свойства и зависимости, управление версиями и импорт BOM.
Не воспроизводится полный контекст сборки Maven: активация профилей,
SNAPSHOT/диапазоны, relocation, дополнительные репозитории,
глобальная медиация конфликтов и принудительное переопределение транзитивных
версий корневым POM. Узлы идентифицируются GAV, type/classifier
сохраняются при чтении объявлений, но не создают отдельные вершины.

Алгоритм и шесть воспроизводимых примеров: [этап 3](docs/stage-3.md).

## Обратные зависимости

```console
py -3 run.py --config examples/reverse/diamond.ini
py -3 run.py --config examples/reverse/httpclient.ini
```

Необязательные ключи INI: `reverse` (по умолчанию false),
`reverse_target` (по умолчанию выбранный пакет).
Поиск выполняется по всему тестовому репозиторию либо внутри
Maven-графа, собранного от `package`. Алгоритм, границы поиска
и примеры: [этап 4](docs/stage-4.md).

## Сравнение со штатным Maven

```console
py -3 tools/compare_maven.py --bootstrap
```

Нужна установленная Java. Скрипт использует Maven из `PATH` или временно
загружает Maven 3.9.9 с проверкой SHA-512. POM потребителя, Maven,
его кеш и результаты создаются во временной папке и удаляются после работы.
Приложение не вызывает этот скрипт и не использует Maven для получения данных.

Для JUnit, SLF4J Simple и HttpClient множества вершин и рёбер совпали
со штатным `dependency:tree`. Команды, точный вывод, версия плагина
и объяснение различий моделей: [результаты сравнения](docs/comparison.md).

## История этапов

Каждый этап сохранён отдельным русским Conventional Commit.
Дата автора совпадает с датой коммитера; часовой пояс — `+03:00`.

| Этап | Дата и время | Сообщение коммита |
| --- | --- | --- |
| 1 | 04.11.2026 19:17:00 | `feat(config): добавить CLI и проверку INI-конфигурации` |
| 2 | 05.11.2026 20:26:00 | `feat(maven): реализовать чтение POM и прямых зависимостей` |
| 3 | 06.11.2026 21:08:00 | `feat(graph): добавить рекурсивный BFS и тестовый репозиторий` |
| 4 | 07.11.2026 22:34:00 | `feat(reverse): добавить поиск обратных зависимостей` |
| 5 | 08.11.2026 23:41:00 | `feat(visualization): добавить PlantUML, SVG и ASCII-дерево` |

Отчёты этапов описывают вывод соответствующего коммита.
На последнем этапе временные списки первых этапов заменены визуализацией.
Для просмотра ранней версии используйте отдельный `git worktree`:

```console
git log --oneline --reverse
git worktree add ../maven-graph-stage-1 <хеш-коммита-первого-этапа>
```

## Структура

```text
src/maven_graph/    исходный код
tests/             автоматические тесты
examples/          INI-файлы и тестовые репозитории
docs/              отчёты по этапам
tools/             проверка оформления, SVG и сравнение с Maven
run.py             переносимая точка входа
run.bat, run.sh     скрипты запуска
```

Сгенерированные изображения, кеши, архивы, бинарные файлы,
настройки редакторов и результаты сборки исключены через `.gitignore`.
